# test

本仓库用于保存 2027 赛季电控硬件组第二轮考核工程。各题工程彼此独立，均保留自己的 `CMakeLists.txt`，使用时应将对应目录单独作为工程根目录打开和编译。

## 仓库目录

- `test_A/`：A 题 GM6020 单电机角度—速度串级 PID 控制工程。
- `test_B/`：B 题双轴云台控制工程，支持 Yaw（偏航）和 Pitch（俯仰）两台 GM6020。
- `test_C/`：C 题双开发板 CAN 通信、角色分配、握手及角度/弧度换算工程。
- `成果展示/`：A、B、C 三道题的图片和视频。

公开 Git 仓库：<https://github.com/rockpunkgod/test>

## A 题完成情况

A 题已经完成 GM6020 单电机闭环控制，实际控制电机 ID 为 2。工程能够独立编译，并已完成速度模式和位置模式实物调试；成果材料中包含速度环 VOFA+ 曲线截图和位置环演示视频。

### 已实现功能

1. 使用 `GM6020_t` 结构体保存编码器、转速、电流、温度、连续相对角度、目标值和 PID 状态。
2. CAN1 工作在 1 Mbps，通过 FIFO0 接收中断解析电机 2 的 `0x206` 反馈。
3. 使用首次有效反馈作为相对角度零点，并处理 8192 线编码器的跨圈回绕。
4. 实现保护、速度、位置三种模式。
5. 位置模式采用角度外环和速度内环串级 PID，角度环输出作为速度环目标值。
6. 反馈超过 100 ms 未更新时，PID 清零并强制输出 0。
7. FreeRTOS 电机任务以 500 Hz 运行，串口命令和遥测任务以 50 Hz 运行。
8. USART1 使用 115200、8N1，与 VOFA+ 双向通信。
9. VOFA+ 同时打印目标角度、实际角度、目标速度、实际速度、模式、控制输出和在线状态。

### A 题 VOFA+ 命令

VOFA+ 串口结尾选择 `\r\n`，输入框中不需要手写换行符。

| 命令 | 含义 |
| --- | --- |
| `M:0` | 保护模式，持续发送零控制量 |
| `M:1` | 速度模式 |
| `M:2` | 位置模式 |
| `S:数值` | 设置目标速度，单位 rpm |
| `P:数值` | 设置目标相对角度，单位 ° |

例如先发送 `M:1`，再发送 `S:100`，即可令电机在速度闭环下以 100 rpm 为目标运行。位置调试时先发送 `M:2`，再发送 `P:30`。结束调试前发送 `M:0`。

### A 题打印数据说明

```text
RM2027:目标角度,实际角度,目标速度,显示速度,模式,控制输出,反馈在线
```

其中显示速度是对 CAN 反馈转速进行一阶低通滤波后的数值，只影响 VOFA+ 显示，不参与 PID 计算。模式值 `0/1/2` 分别表示保护、速度和位置模式；在线值为 `1` 表示最近 100 ms 内收到有效反馈。

### A 题调试中遇到的问题

1. **Kp 增大后电机仍不转**

   最终发现应先检查 CAN 在线状态。只要反馈离线，安全逻辑就会强制输出 0，继续增大 PID 参数不会产生作用。

2. **速度模式无法切换或目标速度始终为 0**

   需要同时保证串口命令格式、模式字段、CAN 反馈和电机 ID 正确。A 题正确命令为 `M:1` 和 `S:目标速度`。

3. **速度稳定但存在稳态偏差**

   比例控制需要保留误差才能产生输出，因此在负载下可能存在偏差。通过小幅加入速度环积分项并限制积分输出改善。

4. **VOFA+ 曲线看起来抖动**

   GM6020 转速反馈是整数 rpm，低速时存在量化跳变。工程只对显示值做低通滤波，控制环仍使用原始反馈，避免显示处理改变控制动态。

5. **CAN 和串口外设切换后突然没有数据**

   调试中曾在 CAN1/CAN2 和多个 USART 之间切换，导致句柄、GPIO、中断或回调不一致。最终工程统一使用 CAN1 和 USART1。

## B 题完成情况

B 题程序功能已经完成。程序同时支持 Yaw 和 Pitch 双轴控制，但成果视频中只展示了 Pitch 电机旋转。原因是现场 Yaw 电机接线位置不方便进行安全、清晰的旋转展示，并不是程序只实现了 Pitch。

### 已实现功能

1. 使用 `GM6020_t motor[3]` 保存两台电机各自的状态。
2. Yaw 使用电机 ID 1，Pitch 使用电机 ID 2。
3. CAN1 工作在 1 Mbps，通过 FIFO0 接收中断处理反馈。
4. 电机 1、2 的反馈标准帧 ID 分别为 `0x205`、`0x206`。
5. 两台电机的控制量合并到一个标准数据帧中发送：电机 1 使用 `DATA[0]、DATA[1]`，电机 2 使用 `DATA[2]、DATA[3]`，当前工程控制帧 ID 为 `0x1FE`。
6. 每台电机均支持保护模式、速度模式和位置模式。
7. 位置模式采用角度外环、速度内环的串级 PID；速度模式只运行速度 PID。
8. 首次有效反馈作为相对角度零点，并通过编码器增量处理回绕，得到连续角度。
9. 超过 100 ms 未收到反馈时，PID 清零并强制输出 0，防止电机失控。
10. FreeRTOS 电机任务每 2 ms 运行一次，即 500 Hz；串口命令和遥测任务每 20 ms 运行一次，即 50 Hz。
11. USART1 使用 115200、8N1，与 VOFA+ 双向通信。
12. 使用 C++ `Gimbal` 类统一管理双轴，同时保留 `extern "C"` 接口供 C 语言生成代码调用，体现“对象保存状态、成员函数操作对象”的面向对象设计。

### B 题控制流程

1. CAN 接收中断取得反馈帧并交给 `Gimbal_ParseFeedback()`。
2. Yaw、Pitch 对象分别根据自己的反馈 ID 判断是否接收该帧。
3. 解析编码器、转速、电流和温度，并更新连续相对角度及最后反馈时间。
4. 500 Hz 控制任务读取当前模式和目标值。
5. 保护模式直接输出 0；速度模式运行速度 PID；位置模式先由角度 PID 算出目标速度，再由速度 PID 算出控制量。
6. Yaw、Pitch 控制量被装入同一个 CAN 控制帧并发送。
7. 50 Hz 串口任务解析 VOFA+ 命令，同时打印两轴遥测数据。

### B 题 VOFA+ 命令

VOFA+ 串口设置为 115200、8N1，命令结尾选择 `\r\n`。输入框内只需要填写命令本身，不需要手写换行符。

| 命令 | 含义 |
| --- | --- |
| `M:0` | 进入保护模式，两台电机输出 0 |
| `M:1` | 进入速度模式 |
| `M:2` | 进入位置模式 |
| `YS:数值` | 设置 Yaw 目标速度，单位 rpm |
| `PS:数值` | 设置 Pitch 目标速度，单位 rpm |
| `YA:数值` | 设置 Yaw 目标相对角度，单位 ° |
| `PA:数值` | 设置 Pitch 目标相对角度，单位 ° |

例如：

```text
M:1
PS:30
M:2
PA:20
M:0
```

速度滑块应生成 `YS:` 或 `PS:` 命令，位置滑块应生成 `YA:` 或 `PA:` 命令。滑块发送周期建议不小于 40～50 ms，避免发送速度超过当前单命令缓冲区的处理能力。

### B 题打印数据说明

打印格式：

```text
RM2027:Yaw目标角度,Yaw实际角度,Yaw目标速度,Yaw实际速度,
Pitch目标角度,Pitch实际角度,Pitch目标速度,Pitch实际速度,
模式,Yaw控制输出,Pitch控制输出,Yaw在线,Pitch在线,CAN接收标志
```

模式值：`0` 为保护模式，`1` 为速度模式，`2` 为位置模式。在线标志为 `1` 表示最近 100 ms 内收到过该电机反馈，为 `0` 表示反馈超时。

### B 题调试中遇到的问题

1. **PID 的 Kp 调得很大，电机仍没有反应**

   原因并不一定是 PID 参数，而是 CAN 没有收到有效反馈。安全逻辑在反馈离线时强制输出 0，因此应先检查在线标志、反馈 ID 和 CAN 接口，再调 PID。

2. **电机 ID 和 CAN 数据位置对应错误**

   电机 ID、反馈 ID、控制帧槽位必须一致。本工程最终确定 Yaw 为电机 1、Pitch 为电机 2，并分别使用前两个控制槽位。

3. **CAN1、CAN2 来回切换后通信中断**

   调试过程中曾切换 CAN 外设，导致句柄、引脚、中断回调和初始化代码不统一。最终统一使用 CAN1，并确保回调只处理 CAN1。

4. **标准帧和扩展帧 ID 掩码错误**

   标准帧应保留 11 位 ID，使用 `0x7FF`；扩展帧应保留 29 位 ID，使用 `0x1FFFFFFF`。错误地把扩展帧也截成 `0x1FF` 会破坏报文 ID。

5. **更换 USART1、USART2、USART6 后串口不再打印**

   串口句柄、GPIO 复用、中断和 VOFA 初始化参数必须使用同一个 USART。最终工程统一为 USART1、115200、8N1。

6. **实际速度稳定，但与目标速度存在偏差**

   单独使用比例项时，负载下通常会存在稳态误差。后续通过小幅增加速度环积分项消除偏差，同时限制积分输出，防止积分饱和。

7. **实际速度曲线抖动**

   需要区分电机真实机械抖动和转速反馈量化造成的曲线跳动。调试时先只显示目标速度与实际速度，再逐步调整速度环参数，避免同时观察过多量纲不同的通道。

8. **在线状态时好时坏**

   在线状态由 100 ms 反馈超时判断。CAN 接收间断、ID 不匹配、总线配置不一致或中断未持续工作，都会造成在线标志反复变化。

9. **VOFA+ 位置滑块控制卡顿**

   串口任务每 20 ms 只处理一条完整命令，而且当前只有一个命令缓冲区。滑块发送过快时，新命令可能被忽略。现阶段将发送周期设为 40～50 ms；进一步优化可改为环形缓冲区或命令队列。

10. **位置环参数过大时动作突然**

    角度误差经过角度环后会转换为目标速度。如果角度环 Kp 或速度限幅太大，小幅拖动也可能快速达到速度上限。应先使用较低速度上限，再从小到大调整角度环 Kp。

### B 题继续使用前的注意事项

- 机械限位应按实际机构重新填写，并保证最小角度小于最大角度。
- 当前调试版本中的 Pitch 限位参数不能作为最终机械限位；正式带机构运行前必须重新确认。
- 每次重新上电后，首次有效反馈位置会成为相对角度零点。
- 调试模式切换或参数变化前，先发送 `M:0` 进入保护模式。
- 成果视频只演示 Pitch，但源代码同时保留了完整的 Yaw/Pitch 双轴实现。

## C 题完成情况

C 题已经完成双开发板 CAN 通信、自动角色分配、握手、角度转弧度和弧度转角度功能，并已完成实物验证。两块板烧录同一份 `test_C` 固件，只需要将连接电脑串口的开发板指定为 A 板；A 板会通过 CAN 自动把另一块未指定角色的开发板设置为 B 板。B 板的计算结果通过 CAN 返回 A 板，再由 A 板统一发送给 VOFA+，因此只需要连接 A 板串口。

### C 题 VOFA+ 使用流程

1. 两块开发板都烧录 `test_C`。
2. 连接两块板的 CAN1 总线并分别供电。
3. 只连接准备作为 A 板的 USART1 到电脑。
4. VOFA+ 设置为 115200、8N1，命令结尾选择 `\r\n`。
5. 发送 `ROLE:A`，A 板开始通过 CAN 自动分配 B 板。
6. 等待打印数据中的“对端在线”和“角色分配成功”都变为 `1`。
7. 再发送握手或换算命令。

### C 题 VOFA+ 命令

| 命令 | 含义 | 示例或预期结果 |
| --- | --- | --- |
| `ROLE:A` | 将当前连接串口的开发板设为 A 板，并自动分配另一块板为 B 板 | 角色字段变为 `1`，角色分配成功字段最终变为 `1` |
| `ROLE:0` | 取消当前板的 A 角色，回到未分配状态 | 角色字段变为 `0`，A 板停止向上位机打印 |
| `H` | 请求 A、B 板握手 | 握手成功和操作完成字段变为 `1` |
| `D:角度` | 请求 B 板把角度转换为弧度 | `D:180` 的结果约为 `3.141593` |
| `R:弧度` | 请求 B 板把弧度转换为角度 | `R:3.1415926` 的结果约为 `180.000000` |

`ROLE:B` 不是有效的串口命令。B 角色由 A 板通过 CAN 自动分配。

### C 题命令执行过程

以 `D:180` 为例：

1. VOFA+ 将 ASCII 字符串 `D:180\r\n` 发给 A 板。
2. A 板串口中断逐字节接收，串口任务解析出角度值 180。
3. A 板把请求、序号和 32 位浮点数装入 CAN 标准数据帧，通过 `0x301` 发给 B 板。
4. B 板收到请求后计算 `180 × π ÷ 180`。
5. B 板把结果装入响应帧，通过 `0x302` 返回 A 板。
6. A 板检查消息类型和序号，保存结果并把操作完成标志置 1。
7. A 板通过 USART1 统一打印 `RM2027:` 遥测，VOFA+ 显示结果。

握手和弧度转角度走相同流程，只是 CAN 消息类型和 B 板执行的运算不同。A 板还会定期发送心跳，用于判断 B 板是否在线。

### C 题打印数据说明

打印格式共有 11 个字段：

```text
RM2027:角色,最后操作,输入值,输出值,操作完成,握手成功,
对端在线,发送计数,接收计数,错误计数,角色分配成功
```

| 序号 | 字段 | 含义 |
| --- | --- | --- |
| 1 | 角色 | `0`=未分配，`1`=A 板，`2`=B 板；实际只由 A 板向 VOFA+ 打印 |
| 2 | 最后操作 | `0`=无操作，`1`=角度转弧度，`2`=弧度转角度，`3`=握手 |
| 3 | 输入值 | 最近一次换算命令的输入；握手时为 0 |
| 4 | 输出值 | B 板返回的换算结果；握手时为 0 |
| 5 | 操作完成 | `1`=已经收到与当前请求对应的回复，`0`=尚未完成 |
| 6 | 握手成功 | `1`=收到 B 板握手确认，`0`=尚未握手成功 |
| 7 | 对端在线 | `1`=最近 300 ms 内收到过对端有效帧，`0`=通信超时 |
| 8 | 发送计数 | 当前板成功提交的 CAN 帧累计数量 |
| 9 | 接收计数 | 当前板接收并通过协议检查的 CAN 帧累计数量 |
| 10 | 错误计数 | CAN 协议错误、无效串口命令、串口溢出和串口错误的累计值 |
| 11 | 角色分配成功 | `1`=A 板已收到 B 板的角色确认，`0`=仍在等待分配成功 |

示例：

```text
RM2027:1,1,180.000000,3.141593,1,0,1,25,24,0,1
```

表示当前为 A 板，最后执行角度转弧度，输入 180°、输出约 3.141593 rad，操作完成、对端在线、角色分配成功，当前没有错误。

### C 题调试中遇到的问题

1. **B 板是否需要单独烧录程序**

   两块开发板都必须烧录 `test_C`，但不需要分别维护 A、B 两份固件。连接串口的板发送 `ROLE:A` 后，另一块未分配角色的板会通过 CAN 自动成为 B 板。

2. **只连接一块板串口能否显示两块板结果**

   可以。B 板只通过 CAN 向 A 板返回结果，A 板负责汇总并通过 USART1 输出，因此电脑只连接 A 板串口。

3. **角色分配成功但对端在线反复变化**

   在线判断依赖心跳回复；B 板未供电、未烧录、CAN 总线不通或两板波特率/接口不一致，都会导致 300 ms 超时。

4. **串口持续打印，但握手和换算不完成**

   串口打印只能证明 A 板正在运行。还需要检查第 7 项对端在线和第 11 项角色分配成功是否为 1，并确认发送的是 `H`、`D:数值` 或 `R:数值`。

5. **通信过程中曾更换 CAN 和 USART 后失效**

   最终统一使用 CAN1 和 USART1。CAN 发送、接收回调、GPIO 和 CubeMX 初始化必须同时指向 CAN1；VOFA 初始化和串口中断必须同时指向 USART1。
